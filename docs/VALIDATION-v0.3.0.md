# v0.3.0 validation scope

This release adds controlled adoption and explicitly opt-in Neovim Shadow Mode.
The existing production integration was not cut over, installed over, reloaded or
used to cycle wallpaper/palette. Private evidence and screenshots are not shipped.

## Review and automated checks

- Reviewed writer/publisher inventory, output aliases, ownership, plan drift,
  error paths, concurrent consumers, rollback and interrupted transactions.
- 88 unit tests cover installation/repetition, unmanaged and edited outputs,
  symlinks, interrupted journals, mode-only drift, foreign manifest edits both
  before and during preflight, token-header validation and visual-gate failure.
- Normal installation with an existing Neovim output refuses adoption and
  preserves it. Installing another selected adapter creates no shadow output or
  shadow consumer/service. Shadow has separate state and explicit commands.
- Ruff, privacy scans of tracked files/full history, Gitleaks of tree/history,
  isolated source CLI smoke, packaging and installed-wheel smoke are release gates.
- GitHub CI tests Python 3.11/3.13 and Nix packaging/secrets. Local offline Nix
  checks cover x86_64-linux; aarch64-linux is not locally built or certified.
- Existing Noctalia MIT templates retain exact provenance hashes and notices;
  no new third-party runtime dependencies or copied plugin implementations.

## Independent native render and screenshots

Noctalia 5.2.1's offline `theme --theme-json --render` rendered the trusted personal
template. Canonical v1 JSON was explicitly converted to its dark/light token-map
format; raw current.json is not assumed compatible. The public core rendered the
same canonical input through `shadow plan/install`, changing only theme identity.

Four dark/light green/purple fixture pairs have identical generated bytes apart
from colorscheme identity, native highlights/Markdown/background, and screenshots.
The repeated release check has 4/4 exact pixel comparisons and successful rollback.
The screenshot gate fails on any mismatch or missing comparisons. This fixed
background fixture uses the documented `NVIM_NOTTYFAST` to avoid startup DSR
timeout warnings contaminating otherwise identical images.

## Installed stack acceptance

An independent private TUI check used Neovim 0.12.4, temporary HOME and all XDG
homes/runtime, copied personal theme/watcher, immutable native runtime, and a
namespace-local RPC socket. Bubblewrap unshared filesystem/session/network/IPC;
no production HOME, display, session bus or compositor sockets were mounted.
Only the private lab was writable; network downloads were unavailable.

The installed personal configuration had no init.lua/init.vim, third-party
plugins or plugin manager. Its guarded watcher was actually loaded from a copy.
Lua, Markdown and markdown_inline Tree-sitter parsers were available; Python's
parser was absent, so Python used native syntax rather than Tree-sitter.

Across dark/light palettes, Lua/Tree-sitter, Python syntax, Markdown/injections,
diagnostics/signs/virtual text, floating windows/borders, native completion and
netrw have 12/12 identical screenshot pairs and equal native highlight data.
The original acceptance also checked 468 RGB-role assertions. The 12-pair TUI
check was repeated against the security-reviewed release code with the same result.
No renderer or highlight-template changes were needed to obtain parity.

Two fixture SSE events changed the output and running preview's actual colors.
The existing foreground consumer, shipped guarded timer and copied personal
watcher were used. The fixture transport listened only inside the isolated network
namespace, not on the production bridge port. SIGINT stopped the consumer with
exit 130 and released its lock. The old writer's separate output did not steal
shadow selection. Returning to the personal test theme restored original
highlight data; rollback removed only owned shadow output. Test processes exited.

## Limits

Native completion and diagnostics used synthetic data, not an installed LSP or
completion plugin. Absent nvim-cmp/blink/Neo-tree and Python Tree-sitter were not
validated. Other Neovim versions/frontends and long-running production sessions
remain outside this acceptance. The built-in `shadow test` uses a clean native
environment, not the user's plugin stack, and is not a filesystem/network sandbox
for an untrusted executable.

The production bridge was inspected read-only; release live-delivery tests used
fixtures. One-shot render is not live integration. Continuous delivery needs an
explicit foreground consumer, and a running preview needs its guarded reload
timer. Production session selection or a permanent consumer requires separate
approval and validation. Ordinary installation enables neither.

Checksums narrow races but do not provide an OS compare-and-swap with unrelated
editors. Recovery stops on unknown content/permission/manifest drift and retains
the journal. An ambiguous legacy journal may require manual reconciliation;
there is no force-overwrite recovery path or global desktop-snapshot guarantee.
